# admin CSS 结构盘点 —— 哪些该吸收进 DS

**目的**：owner 明确要求 admin 的 style **不删**，里面的好结构应吸收进 DS。本文是给
owner 勾选的清单，不是删除计划。勾中的做成组件，没勾的原样留着。

**规模**：146 个 CSS 文件、12857 行、约 2500 个选择器。按前缀分是 20 个业务域
（`vx-tenant` 462 / `vx-product` 258 / `admin-overview` 237 / `vx-admin` 209 …），
但**跨域重复的结构**才是候选——只在一个域出现的是页面样式，不是模式。

---

## A · 建议进 DS（结构可复用、零业务语义）

| #   | 结构                                                           | 出现                   | DS 现状                                    | 缺口                                                                                                             |
| --- | -------------------------------------------------------------- | ---------------------- | ------------------------------------------ | ---------------------------------------------------------------------------------------------------------------- |
| A1  | **带卡内指标的列表卡** `*-directory-card`                      | 4 域 17 处             | `ListCard` 有标题/描述/图标/状态/操作/meta | **缺卡内指标网格**（3 列 label+value）与**语气色条**（顶缘按 tone 染色）。这就是 owner 点名的"多组合内容的 card" |
| A2  | **目录行栅格** `*-directory-list` / `__header` / `-row`        | **170 处**，几乎每个域 | `DataTable` 有列/选择/序号/行操作          | 缺**卡片与表格共用同一套列定义**的能力：admin 的行与卡是同一份数据的两种排布，现在各写一套栅格                   |
| A3  | **可选中操作行** `*-operation-row` + `--selected` + `__select` | 13×3                   | `DataTable` 有 selectedKeys                | 缺**卡片形态下的选中态**（DataTable 只管表格）                                                                   |
| A4  | **详情行** `*-detail-row` / `detail-list__row`                 | 12+                    | `DetailList` / `DetailRow` 已有            | 基本可直接换，无需新件                                                                                           |
| A5  | **状态点** `*-status-dot`                                      | 14                     | `Badge` / `StatusBadge` 有徽章             | 缺**纯圆点**形态（无文字，只表示在线/生效）                                                                      |

## 需要 owner 拍板的三点

**① A1 做成什么形态？** ~~两条路~~ —— **已被后续工作回答（2026-08-05 复核）**：
`MetricListCard` 已存在于 `design-ui/src/components/composite/data/`，走的是"新建、
边界清晰"那条路。悬念只剩它是否覆盖 admin 的 4 域 17 处用法，属核实不属决策。

同批复核还发现：`MetricCard` 的 props 本就是照 admin 的 `SummaryItem` 抽象的（注释里
写明"admin KPI 卡的既有视觉…2026-08-03 opera 对照 admin 实测"）。**DS 已经吸收了
一部分 admin 结构，admin 自己没回接。**

**② A2 值不值得做？** 它出现 170 次、收益最大，但也最难：要让**同一份列定义同时驱动表格行与卡片**，等于给 `DataTable` 加一个 `cards` 渲染模式。做对了四个门户都受益，做歪了会变成一个谁都不敢碰的巨件。可以先只做 A1/A3/A5，A2 留到列表页迁移时看实际需要。

**③ B 里的 pill 映射表放哪？** 留在 admin（`modules/shared/`），还是上提到 `@vxture/shared` 的值域（那里已经有 `SUBSCRIPTION_STATUSES` 等业务值域）？后者能让 console 复用同一套状态文案与色调。

---

## 与批 B/C 的关系

本盘点是 3.2（列表页迁 DS）/3.3（详情页迁 DS）的**前置**。顺序是「盘点 → owner 挑 → 挑中的成组件 → 再迁页面」，不是「迁页面顺手删 CSS」——跳过这一步，这些结构会在迁移中被无声丢掉。
