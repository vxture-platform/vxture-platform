**B4a / B4b-1 / B4b-2 完成记录（2026-08-14）**：

- **拆分判据是频次不是主题**：产品登记一次性、OIDC 凭据要轮换要按渠道加要临时禁用；
  且原抽屉按产品过滤，「哪些客户端还开着」这类横向问题在任何一个抽屉里都答不出来。
  新页默认列**全部**产品的客户端，`?productId=` 深链保留原抽屉的等价用法。
- **权益配置按产品逐个看，不做全量矩阵**——不是偷懒是上游形状：runos 只有按主体查和
  按能力查，**没有列全部授权的接口**，全量矩阵要 N 个来回。Atlas 侧有全量接口，所以
  产品选择器上的路由授权条数是真的；能力授权条数选中后才知道，界面上如实说明。
- **五条深链原本全是空的**。加完页面才发现目标页读的参数名不同或根本不读
  （`/model/grants` 只认 `endpointCode`、`/model/routes` 只认 `modelCode`、
  `/capability/grants` 与 `/product/catalog` 什么都不读），跳过去看到的是全量列表——
  不报错的那类失败。四个目标页逐个补了参数与「只显示 X · 显示全部」横幅。
- **验证态是推导的，不加字段**。`product.launch_checklist_items` +
  `product_launch_statuses` 已经在库里（8 项，商业 2 项归 admin、技术 6 项归 opera），
  验证态 = 必填项的满足情况；待我方 / 待对方按「这一项平台能不能单方面完成」划分
  （C1/C2/C3 三项平台**观测不到**，勾选是操作员按对方回报做的判断）。
  新增 `GET /api/products/checklist-summary` 一条 SQL 取回全部产品的完成态，
  避免列表页 N 次往返。
- **状态机守卫立在 BFF**：`PATCH :id/status` 此前**任意值都放行**，「终态」只是界面上
  的约定，任何直连的脚本都能把已退役的产品改回 active。现在读当前态 + `FOR UPDATE`
  锁行再判迁移边，幂等重放（active → active）不报错也不写库。
- **门槛失效必须失效在保守那一侧**：确认上线要求必填检查项全满足，而汇总接口失败时
  前端拿到的是空数组——「没有未满足项」与「不知道有没有未满足项」在数组上长得一模一样。
  第一版按"空=全通过"处理，等于上游一挂人人可上线；已改成读不到就挡住并说明原因。

**B4b-3 / B4b-4 完成记录（2026-08-14）**：

- 流程页 `/product/launch?productId=`，**不进导航**（设计 §6.5：接入是低频动作，未完成
  的接入本来就以草稿行躺在目录里）。三个入口全在目录页：主按钮「接入产品」= 建草稿后
  **直接跳进流程页**；草稿行「继续接入」；正式行「重新验证」。已退役行给「查看接入记录」。
- **确认上线先重跑再判**，不看页面上已有的结果（设计 §6.4 约束一）。重跑全过 + 检查单
  必填项全满足才跃迁；任一不过只出报告，**不改生命周期状态、不回滚草稿**。
- **已上线的产品在这页只复验**：横幅明确写「验证失败不会自动停用」（约束二）——自动停用

## B5 · 能力用量

| #    | 任务                                                                       | 状态 |
| ---- | -------------------------------------------------------------------------- | ---- |
| B5-1 | opera-bff 代理 runos `GET /audit/usage-summaries`（七轴，v0.5.0 已在生产） | ✅   |
| B5-2 | 能力管理新增「用量计量」页，轴切换比照模型侧计量页                         | ✅   |
| B5-3 | 工作区显示复用 `features/tenancy`（租户主导，见该模块文件头）              | ✅   |

**背景**：这是目前唯一「上游已交付、opera 未接」的面（起于 `vxture-runos#81`）。

**完成记录（2026-08-14）**：

- **七根轴**（上游 `USAGE_AXES`）：`workspace`（默认）/ `tenant` / `product` / `agent` /
  `provider` / `capability` / `endpoint`。响应是**信封**不是裸数组
  （`{dimension, from, to, rows}`）——窗口边界跟着行一起回来，否则前端只能猜自己看的是
  哪段时间。字段名逐个对着 runos 源码核过（`productId` 不是 `productCode`、`provider`
  不是 `providerCode`、`endpointInstanceId`），没有照文档推。
- **四条上游契约页面如实转达，没有替它抹平**：
  1. **恰好返回 `limit` 行 = top-N 截断，合计少算**。这是最容易出错的一条——截断后的
     合计看起来是个完整的数。页面此时**整块隐藏合计卡片**并换成警告横幅；导出的 CSV
     里也追加一行说明，因为文件会脱离页面独自流传。
  2. 历史从首次部署起、不回填——空窗口的文案写的是「从来没被记过」而不是「用量为零」。
  3. `none` 是**可见的哨兵分组**，原样显示不美化成「未知」：正因为它不被丢掉，七根轴的
     总数才彼此相等。
  4. `costAmount` 是**运营口径不是账单事实**（runos 契约原话：不预判 product_110 §6.8#1
     的计费归属裁定），列头就叫「成本（运营口径）」。
- **列随轴变**，不画七轴通用的宽表：不属于当前轴的身份字段是 `null` 而非缺数据。两个
  例外被利用起来——`workspace` 行带 `tenantId`（于是走平台的租户主导显示，B5-3），
  `endpoint` 行带 `capabilityId`（单看端点实例 id 没有意义）。
- **成功率按「成功 / 放行」算**，不按「成功 / 调用」：被裁决挡掉的那些从来没跑过，算进
  分母会把一次严格的策略读成一次故障。口径写在指标卡的 `help` 里。
- 轴写错、日期解析不了，上游都回 400 并说明原因——BFF **原样透传不代为兜底**，页面直接
  展示那句话。把写错的轴悄悄渲染成默认轴的数据，比报错更容易被当成真答案。
- 顺带清掉两个**因本批与 B4 而变成零消费方**的占位组件（`PendingBatchPage` 的三个消费页
  已全部建成，`PlannedManagementPage` 的两个页在 B2 已删）。带着自信文档的死代码比没有
  代码更误导。

  之前屏幕上那份最多 30 秒前的旧数据**看起来和刚刷新的一模一样**。新 hook 隐藏即
