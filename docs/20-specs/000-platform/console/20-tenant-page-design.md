## 0. 一句话

「租户信息」是「账户与租户」板块下的**一个二级页面**,与「账号信息」并列;页面正文是五张卡 + 一张危险操作卡,骨架、缩进、页底保存与账号信息页完全一致。今天的「租户信息 / 组织信息 / 系统设置」三个二级页面合成这一个。**个人租户 = 只有一个用户的组织租户**:同一页、同一套卡、同一批字段,差异只落在身份卡的徽章与危险操作的动作上——个人转组织因此是平滑的,只改类型、名称和编号,页面不换。

集合(成员 / 邀请 / 角色 / 工作空间 / 订阅 / 审计)**不进这页**:各归各的列表页(侧栏就是那排 tab),租户页只给数量与入口,不做页内 tab。万人租户在「成员管理」页用表格 + 搜索 + 翻页管;那页今天是 BFF 全量返回、前端翻页,万人要改服务端分页,归成员页后续。

## 3. 页面结构

页头:与账号信息页同一 `ViewHeader`,不加面包屑、不加返回(返回只给三级子页)。自上而下:

### 3.1 身份卡(一张卡,不卡套卡)

- 左:Logo(点击上传 / 清除,即时动作)。
- 中:名称 + 类型徽章(个人租户 / 组织租户)+ 状态徽章(正常 / 停用)+ 认证徽章(未认证 / 审核中 / 已认证 / 认证失败 / 已作废);第二行 `T-{tenant_no}` · 创建时间 · 所有者 · 成员 N(组织,链到成员管理),块间 gap-lg。
- 右:认证按钮(个人 → 去账号信息实名 / 查看;组织 → 去企业认证 / 查看)。
- 右下角:「工作空间 · N ▾」展开,每行 名称 · 默认标签 · `W-` 编号 · 成员数;只列、不建、不切(切换在顶栏租户面板);多工作空间落地后最多列 5 个,多了给「查看全部」。
- **不展示产品订阅**(多产品 SaaS,订阅归订阅板块)。

租户类型、认证、创建时间、工作空间只在这里出现一次,下面的信息卡不再重复。

### 3.2 基本信息

租户名称 · 简介 · 所属行业 · 企业规模 · 官网(原「经营信息」并入)。只读态 → 「修改」激活 → 随页底保存。两种租户类型字段一样,允许为空。

### 3.3 联系人(管理员 / 联系人)

联系人 · 职务 · 邮箱 · 电话 · 国家 / 地区 · 地址 · 邮编 · 账单接收人(开关)。租户的官方对外窗口:认证结果、账单与发票通知投递到这里。个人租户默认取账号的手机 / 邮箱,可改。

### 3.4 默认区域

默认语言 · 默认时区 · 结算货币,三个下拉,与账号信息页「个人偏好」同款控件,宽度 300px 档(token `overlay-lg` = 288px;账号信息页的个人偏好同步改这一档)。租户层默认值,工作空间继承;与个人偏好里的界面语言 / 时区是两回事,不互相覆盖。

### 3.5 租户策略(规划中,折叠)

访问(邀请审批 / 外部成员 / 默认角色)· 安全(强制二次验证 / 可信设备 / 会话时长)· 数据(审计保留期 / 导出审批 / API Key)。默认折叠、控件禁用、不再写 localStorage。

### 3.6 危险操作(整卡红,与账号信息页同款)

| 动作         | 个人     | 组织     | 形态                                                                                                                                                                |
| ------------ | -------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 转为组织租户 | ●(owner) | —        | 对话框 + ≥5 秒进度仪式 + 完成页,见 §4                                                                                                                               |
| 转让所有权   | —        | ●(owner) | 选一名活跃成员 → 输入租户名称确认 → 立即生效;你降为管理员                                                                                                           |
| 注销租户     | —        | ●(owner) | 本期只画入口(禁用)+ 条件标签(无未清账单 · 无付费余额 · 无进行中退款开票 · 无已付款待确认订单 · 成员已清退);后端另起一批,资格复用批 5b 的 `TenantClosureReadService` |

### 3.7 页底

保存 / 放弃粘底,覆盖:名称、简介、行业、规模、官网、联系人八项、默认区域三项——一次 `PUT /api/me/organization`。Logo、认证、危险操作是即时动作,不进草稿。

## 4. 转为组织租户

不可回退(B9b 触发器直接拒绝组织→个人)。owner 且 personal 才放行,否则 409;钱和订阅都不动,不需要清账阻断。

### 4.1 转换后

| 维度                          | 转换后                                               | 说明                                                                       |
| ----------------------------- | ---------------------------------------------------- | -------------------------------------------------------------------------- |
| 类型 / 名称                   | organization / 对话框里填的组织名称                  | 页面结构不变                                                               |
| `T-` / `W-` 编号              | **一动不动**                                         | 主体码 v4 三号解耦:号里不含归属,转换无需换发(本地库实测通过)               |
| 认证                          | 重置为「未认证」,入口变企业认证                      | 个人实名留在账号上不受影响                                                 |
| 成员                          | 成员 / 邀请 / 角色三页出现;你是唯一成员、owner       | 导航按租户类型显隐                                                         |
| 订阅 / 余额 / 账单 / 工作空间 | 全部原样跟着租户                                     | tenant id 不变;新订单付款时效改 2880 分钟                                  |
| 个人租户                      | **转换事务里立刻补建**一个新的个人租户(取自己的新号) | owner 2026-09-05 定;不靠下次登录的 onboarding 补建;v4 下无「收回旧号」一说 |
| 默认租户                      | **新的组织租户**(同 id,当前会话的 active_org 就是它) | 顶栏租户面板多出新的个人租户,可切过去                                      |

### 4.2 过程:正式、有视觉进度、至少 5 秒

后端是一个事务,几百毫秒就完;但这是租户的身份变更,前端做成一段有步骤的仪式:每步至少 1 秒、整段不少于 5 秒,服务端返回早了就等到时间、返回晚了就等结果,失败只在对应步骤上亮红。

1. **对话框「转为组织租户」**:组织名称(必填)· 知悉四项(认证重置 / 开启成员管理 / 付款时效改 2 天 / 不可回退)· 输入当前租户名称确认 · 「开始转换」。

   > **实施时的一处修正(2026-09-05)**:第二屏改为**事务成功之后**的回放。原设计让进度条与事务并行、按时长逐步打勾——事务失败时前几步的勾就是假的,用户会看到「已变更类型」然后被告知失败,不知道到底改没改。现在是先提交、成功才进第二屏,每步展示的是**已经发生的事实**;失败则根本不进第二屏,错误留在第一屏。仪式感照旧(≥5 秒、逐步亮起),但它不会撒谎。

2. **转换中(整页遮罩,不可关闭)**:① 核对所有者与租户状态 → ② 变更租户类型与名称 → ③ 重置认证状态 → ④ 补建你的新个人租户 → ⑤ 切换到组织租户、刷新会话。①–④ 对应同一个后端事务,前端按最小时长逐步亮起;事务失败则当前步骤变红、给「重试 / 关闭」,租户保持原样(事务回滚)。⑤ 是前端动作:`refreshSession` 拿到新类型 / 名称 / 编号后再放行。
3. **完成**:「X 已成为组织租户」· 租户编号不变 · 你的新个人租户 T-新号 已就绪 · 「进入组织租户」(默认)/「去企业认证」。关闭后页面已是组织形态。

### 4.3 后端

`POST /api/me/organization/convert {name}`:一个事务——锁租户行 → `type='organization'`、`name`、`verification_status='unverified'`(**不动 tenant_no,v4 已无换发触发器**)→ 用既有 `provisionOrg(owner,'personal',null)` 补建个人租户 + 默认工作空间 + owner 成员关系(触发器给它一个新的类别位 2 号)→ 返回新个人租户 id。`tenancy.tenants.type` 已在 98 的 UPDATE 白名单里,不必另授权。

> 转换之所以这么轻,是因为主体码 v4「三号解耦」(2026-09-05,见 `data_identity_200_schema.md` §11)把归属从号里摘了出去。v3 时代它要连带换发租户号、整批改写空间号前缀,并且不可逆;现在只是两个字段的 UPDATE。

## 5. 认证子页 `/tenant/verification`

租户信息页只放一个徽章和一个按钮,认证本身是状态机 + 历史,留在独立三级子页(规格 §3.4),有返回「租户信息」。个人租户不开这页:身份卡按钮指向账号信息的个人实名。

- **状态条**五态:未认证 · 审核中 · 已认证(通过时间)· 认证失败(驳回原因)· **已作废**(名称变更)。审核中只读;失败与作废开放重新提交。
- **当前认证信息**(已认证时):企业全称(= 租户名称,认证时快照)· 统一社会信用代码 · 法定代表人 · 通过时间。
- **申请 / 重新提交**:统一社会信用代码(18 位校验)· 法定代表人;营业执照上传列已在库里(`business_license_image_ref`),表单本期沿用两字段,上传另起。审核在运营台既有台账,通过 / 驳回同步租户认证状态。
- **历史记录**(时间线,最新在上):提交 · 通过(审核人)· 驳回(原因)· 作废(名称由 A 改为 B)。

### 5.1 更名认证规则

- **触发**:组织租户改名(基本信息里「租户名称」保存)时,若当前认证为「已认证」或「审核中」,改名确认框先说清后果:原认证作废、需重新认证。
- **落库**:当前认证记录状态置为 `superseded`(作废,备注「名称变更:A → B」),`tenants.verification_status → unverified`;身份卡徽章立刻变「未认证」,历史多一条「作废」。`kyc.tenant_verifications.status` 的 CHECK 现在只有 unverified / pending / verified / rejected,**加 superseded 进本批迁移**。
- **个人租户**改名不涉及认证(实名在账号上)。转为组织租户时同样走「作废」口径:个人租户没有企业认证记录,只重置租户认证状态。
- **前置**(规格决策 1:经办人须先个人实名)本期不启用校验——个人实名还是规划中骨架,启用等于把企业认证一起锁死;等个人实名落地再开。

## 6.1 编号展示

三个主体码统一带字母前缀(主体码 v4「三号解耦」,见 [`data_identity_200_schema.md`](../../../30-design/data_identity_200_schema.md) §11):用户 `U-` · 租户 `T-` · 工作空间 `W-`。号形 10 位 = 类别位 + 随机 8 位 + Luhn 校验位,不分组展示。格式化收口在 `portals/console/src/lib/principal-no.ts`,页面里不要手拼前缀。

三个号**互不推导**:身份卡上的租户号与其所有者的用户号毫无关系,工作空间号也与租户号无关。要「一眼看归属」由页面并列展示,不靠号推导。

## 7. 导航 · 路由 · 权限 · 迁移

- **导航**:「账户与租户」= 账号信息 · 租户信息(一条,不按类型分);「高级设置」= 通知提醒 · 审计日志;系统设置退役。通知提醒是系统设置,单独保留,不进租户信息也不进账号信息。
- **路由**:新页 `/tenant`;`/personal-tenant`、`/organization`、`/settings`、`/tenant-settings` 跳转 `/tenant`;企业认证 `/organization/verification` → `/tenant/verification`(旧路径跳转)。
- **权限**:全员可读;修改 / Logo / 保存按 `tenant.settings.manage`;危险操作只给当前 owner(仓储层再判一次)。
