# Console「账号信息」页设计(批 5a / 5b)

> 状态:已上线(5a v0.26.69 · 走查修正 v0.26.70 / v0.26.72 · 5b 删除账号 v0.26.71),本文按实际形态记录
> 范围:`/profile` 页面结构、字段、交互、删除账号全流程。个人实名子页 `/profile/verification` 仍是规划中骨架。
> 上游规格:[`docs/20-specs/20-vxture-tenant-console-info-spec.md`](../../20-vxture-tenant-console-info-spec.md) §一(个人信息)
> 姊妹文档:[`20-tenant-page-design.md`](./20-tenant-page-design.md)(租户信息页,同一套骨架)

---

## 0. 一句话

「账号信息」是「账户与租户」板块下的**一个二级页面**(`/profile`),与「租户信息」并列。页面正文是五张卡 + 一张危险操作卡,页头是 `ViewHeader`,不加面包屑、不加返回。原「安全设置」页(`/security`)已并入本页,旧路由跳转 `/profile?panel=sessions` 并展开会话。

**这一页只放账号(人)的属性**;租户的属性在租户信息页,集合类(成员 / 订阅 / 账单)各归各的列表页。

---

## 1. 卡序与骨架

自上而下:身份卡 → 基本信息 → 个人偏好 → 安全设置 → 三方登录 → 危险操作 → 页底保存 / 放弃(粘底)。

**缩进(owner 2026-09-04 两轮走查定稿)**:卡片正文照 `SectionHeader` 的骨架留一个 `icon-lg` + `gap-lg` 的占位(`CardRows`),字段名因此落在**面头标题文字**那条竖线上;名列宽 `media-2xl`(v1 的 `media-3xl` 名值间距过大)。行内展开区(登录历史 / 活跃会话)用 `RowExpand`,占位与名列同宽,框的左缘与**值列**对齐。

**一行多信息**用 `gap-md` / `gap-lg` 排开,不用「·」拼串;徽章紧跟主值。

---

## 2. 身份卡

一张卡,**不卡套卡**(`IdentityCard frame={false}` 套在外层卡里)。

- 左:头像(点击上传,右下角编辑角标;可清除)。
- 中:显示名 + 账号状态徽章;第二行 `U-{user_no}` + 注册时间。**不写「控制台用户」**。
- 右:清除头像 · 去认证。
- 右下角:「所在租户 · N 个 ▾」开关,**默认收起**。

**所在租户展开区**(一次列全,不给切换——切换在顶栏租户面板):每行
首字母牌(宽 `icon-lg`,与下方各卡标题同一竖线)· 租户名 · 标签按 **类型 → 角色 → 当前** 顺序 · `T-{tenant_no}` · 加入时间 · 「租户信息 →」;第二行工作区与租户名左对齐、字号小一档,多工作区同一行用间距分隔,默认工作区在最前。租户之间**实线**分隔,两行间 `gap-xs`。

> 角色标签用 `StatusBadge` 的 `icon` prop(owner / manager / 其它 三档图标);子元素里再塞一个 `Icon` 会出双图标,这是走查抓到的 bug。

## 3. 基本信息(五行)

| 行       | 形态                                                                                                                                                                              |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 显示名称 | 默认只读灰输入框;点「修改」激活,随页底保存                                                                                                                                        |
| 账号     | 等宽字体 + 徽章:按「账号密码登录」开关显示 **可登录** / **禁止登录**;禁止时 tooltip「使用手机 / 邮箱 / 三方动态验证登录」。改名冷却期未过时补一枚提示徽章。动作按钮统一叫「修改」 |
| 手机     | 已验证 / 未验证徽章;「验证」(未验证时)+「更换」两步 OTP 流程                                                                                                                      |
| 邮箱     | 同上                                                                                                                                                                              |
| 最近登录 | 时间 · IP · 地区 · 系统 / 浏览器;行尾「登录历史 ▾」行内下拉                                                                                                                       |

**登录历史**:默认露 **3 条**,其余点「更多 N 条 / 收起」;结果徽章(成功 / 失败)靠右;窗口 **近 30 天**(仓储层 `listLoginHistory` 加了时间条件,BFF 上限 50)。

简介字段已删除。

## 4. 个人偏好

语言、时区走下拉;主题、密度、文字大小走按钮组。**五个控件同宽同高**:宽 `media-3xl`(≈200px),高统一 `h-control-md`(按钮组用 `md` 档才与下拉齐平),按钮组 `p-0` 让分段上下填满外框而不越过描边。

主题 / 密度 / 字号**即时预览**,「放弃」回滚,「保存」才写 platform-browser 的跨门户持久化;语言保存后按新语言重载。

> 与租户信息页的「默认区域」是两回事:这里是**你自己看到的界面**,那里是**租户的默认值**,互不覆盖。

---

## 5. 安全设置

密码(设置 / 修改,后端 ≥ 8 位)· 账号密码登录开关(关闭前二次确认;后端拒绝关掉最后一条登录通路)· 二次验证(规划中,占位禁用)· 活跃会话。

**活跃会话**:行尾「管理会话 ▾」行内下拉,每行 系统 / 浏览器 · IP · 登录方式 · 最后活跃 + 「下线」。

> **会话列表曾恒为 0**(走查抓到,v0.26.72 修):OIDC 登录只写 Redis 中央会话,持久镜像表 `session.auth_sessions` 从来没人写。现在 auth-bff 的 `finishTenantLogin` 用**同一个 sid** 落镜像行(IP / UA / 登录方式 / 到期),`end_session` 翻 `revoked`;刷新令牌、静默 SSO、跨标签恢复三条路径回查镜像状态——**有行才判**,本改动之前的老会话没有镜像行,不会被误踢。console「下线此设备」因此在对方下次刷新时真正生效。

---

## 6. 三方登录

**开放式登录**口径(用 Google / 飞书 / 钉钉 / 微信 账号直接登录 Vxture,与组织无关)。两个维度分开:

- **值列 = 绑定状态**:已绑定 / 未绑定 + 该家的说明句(「用钉钉账号登录」这类),已绑定的补一条绑定日期。**不显示绑定的账号 id**(打码的 id 对用户没有意义)。
- **动作列 = 接入状态**:平台尚未接入的显示「对接中」徽章、无按钮;已接入未绑定的给「绑定」;已绑定的可「解绑」。哪家接入了是配置(`INTEGRATED_PROVIDERS`,当前为空集),不是代码。

按钮一律 icon + 文字。

## 7. 危险操作:删除账号(批 5b)

**整卡红色警示**:描边 + 淡红底 + 面头图标 / 标题着色。面头说明是「**删除条件**」红色加粗前缀 + 五枚 danger 标签(不是组织所有者 / 无未清账单 / 无付费余额 / 无进行中退款或开票 / 无已付款待确认订单)。入口按钮是红描边的 `outline`(它只打开两步流程的第一屏),落锤在对话框的 `DialogForm danger` 提交按钮。

### 7.1 资格判定(owner 2026-09-04 裁定)

判定范围 = 本人是所有者的租户(个人 + 组织)。

| 类别     | 项                                                                                                             | 判据                                                                                          |
| -------- | -------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| **阻断** | 组织租户所有者                                                                                                 | `tenants.owner_user_id = 本人 and type='organization'`                                        |
|          | 未清账单                                                                                                       | `bill_status in (unpaid, paying, partial, overdue)`                                           |
|          | 付费余额 > 0                                                                                                   | 付费余额 = `min(credits.balance, Σrecharge − Σrefund)`,**先消耗赠送**;库里一池不分账,从流水推 |
|          | 进行中退款                                                                                                     | `audit_status='pending'`,或 approved 且 `refund_status in (pending, processing)`              |
|          | 进行中开票                                                                                                     | `invoice_status in (applying, approved)`                                                      |
|          | 有钱在途的待付订单                                                                                             | `pending_verify`,或账单已有实收,或存在待核实付款腿(与订单取消的 409 条件同源)                 |
| **确认** | 订阅未到期                                                                                                     | 剩余周期作废                                                                                  |
|          | 赠送余额                                                                                                       | 作废                                                                                          |
| **自动** | 无款待付订单取消 · 非所有者组织成员关系解除 · 会话与刷新令牌全部吊销 · 三方绑定解除 · 本人发出的待接受邀请撤销 | 申请时即做;任一失败则不动账号                                                                 |
|          | 个人租户软删                                                                                                   | **清扫时**做(保留期内撤销无需恢复)                                                            |

### 7.2 流程

对话框打开即读资格快照:阻断项(红)/ 确认项(黄)/ 自动项(灰),勾「我已知悉」才能提交;有阻断项时提交禁用。提交时 BFF **再判一次**,409 就重读快照把新阻断画出来。成功后立即登出。

### 7.3 保留期

30 天。`account.users.status='deleting'` + `deletion_requested_at`。保留期内**仍可登录**(读谓词放行 `deleting`),但 console-bff 对该用户除会话恢复四条读与 `/api/me/deletion*` 三条外一律 `403 ACCOUNT_DELETING`;外壳据此只画一页:「账号在删除保留期」+ 申请时刻 / 永久删除时刻 + 「撤销删除并重新启用」/「保持删除并退出」。不套外壳(走不通的壳等于请人按按不动的按钮)。

到期由 platform-api 的 `account-deletion-purge` 作业(15 分钟一轮)先软删个人租户,再脱敏 + 软删账号:`account = deleted_{user_no}`、`email` 置空、`phone = deleted:{id 前缀}`、资料清空、凭据 / 三方 / 头像整行删除。**`user_no` 永不回收**,订单 / 账单 / 审计里的裸 `user_id` 仍可解引用到「一个已删除的用户」。

## 8. 编号展示

三个主体码统一带字母前缀(主体码 v4「三号解耦」,见 [`data_identity_200_schema.md`](../../../30-design/data_identity_200_schema.md) §11):

| 主体     | 前缀 | 出现在                              |
| -------- | ---- | ----------------------------------- |
| 用户     | `U-` | 身份卡第二行                        |
| 租户     | `T-` | 身份卡的所在租户展开区;顶栏租户面板 |
| 工作空间 | `W-` | 租户信息页;订单详情;工作区选择器    |

号形 10 位 = 类别位 + 随机 8 位 + Luhn 校验位,不分组展示(复制进工单 / 搜索框不必剔空格)。格式化收口在 `portals/console/src/lib/principal-no.ts`,不要在页面里手拼前缀——旧代码曾有三套写法(`USR_ID: 1799…` / `T-2765…` / 工作空间裸号)。

**带不带字段名,看它在哪**(owner 2026-09-05):

- **独立成条的事实**要带字段名 —— 身份卡第二行读作「用户编号 `U-1799729056`」,因为它旁边是「注册于 2026-03-12」这类带名的事实,中间夹一个裸号读不出是什么。
- **行内标识**只带前缀 —— 所在租户展开区的 `T-` 号、工作空间的 `W-` 号,所在的那一行本身已经说明了它是什么,再加字段名只是把行撑长。

字段名与前缀不互相替代:**字段名是给页面上的人看的,前缀是跟着号被复制进工单 / 搜索框的**。

---

## 9. 页底与读取

保存 / 放弃粘底,覆盖显示名称与五项偏好;显示未保存改动数,无改动时置灰。头像、密码、手机、邮箱、登录开关、三方绑定、删除账号是即时动作,不进草稿。

读一律 `allSettled` + `loadFailed` 显影;错误兜底 `err instanceof ConsoleBffError && err.message ? err.message : t(…)`。会话列表**懒读**:展开时才取一次,守卫用 ref 而不是 effect 的 cleanup 标记——后者会被自己 `setLoading` 触发的重跑掐掉,导致「加载中」永不结束(走查抓到的 bug)。
